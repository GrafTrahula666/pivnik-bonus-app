## Проверяемый контракт будущей реализации (не решение о включении)

1. Клиент и браузер не выбирают тариф, tenant, store, subscription или статус оплаты как источник полномочий. Права опираются на независимо проверенную подпись/issuer, canonical tenant/store binding, действующее состояние подписки и утверждённую политику.
2. События renewal/termination/cancel/replay обрабатываются идемпотентно и в правильном порядке, с default-deny на gaps, reconciliation holds, expired proof и foreign scope.
3. FREE / TRIAL / GRACE / EXPIRED_READ_ONLY, если будут утверждены, получают отдельные **явные** переходы и server-side feature matrix. Unknown не считается active.
4. Данные остаются целыми; никакой автоматической destructive migration; восстановление оплаченных функций допускается только по достоверному provider/payment proof.
5. До подтверждения реальных E07–E09 / issuer / live provider verification нет коммерческого включения, новых платных API или обещаний E2E.

### Рекомендуемая модель решений: **не включать до согласования**

Это **proposal**, не принятая коммерческая политика, не работающий код и не provider entitlement.

| Ситуация | Рекомендованная реакция до одобрения владельцем/Эвотором | Данные |
| --- | --- | --- |
| Неизвестный/непроверенный источник лицензии, пропуск sequence, чужой tenant/store | Запретить новые платные capabilities, не расширять scope по UI или callback | Не изменять, сохранить для безопасной сверки |
| Предполагаемый TRIAL | Не выдавать trial, пока не утверждены длительность, eligible scope, proof/issuer и договорные условия (не более 14 дней согласно публичной тарификации) | Сохранять существующие данные |
| Подтверждённая оплата в пределах доказанного периода | Подключение платных функций **только после** утверждённого тарифа, проверенного provider proof, exact scope и транзакционного guard; сейчас такой production-путь отсутствует | Применять текущие права владельца/tenant |
| Продление не состоялось / dunning | Не выдумывать дополнительный grace. Временное право возможно только по документированному статусу/периоду и согласованной политике; никакого бесплатного обхода API Эвотора | Не удалять |
| Терминальная отмена, отсутствие действующей лицензии | Блокировать новые платные API, синхронизацию и marketing/AI; никакого автоматического downgrade в START/FREE | Сохранять в рамках утверждённого хранения |
| Вход владельца после завершения | **Предложение:** отдельный account/billing recovery UI, без доступа к платным данным и API; просмотр **локально сохранённых исторических данных** / экспорт — только если договор, права пользователя и политика данных прямо разрешат | Никаких автоматических destructive writes |
| Повторная подтверждённая покупка/новая подписка | Возврат доступа только после новой проверенной подписки, current issuer/binding и canonical scope; запрещено оживлять старые права по одному callback | Не перезаписывать исторический ledger |

**Критическое разграничение:** `EXPIRED_READ_ONLY` пока исключительно UX/коммерческая гипотеза. Он **не означает** права после прекращения лицензии продолжать читать REST API Эвотора или запускать бесплатные синхронизации. Если договор не разрешает локальный просмотр/экспорт, доступ после окончания ограничивается восстановлением подписки, поддержкой и минимальной информацией о состоянии аккаунта. Независимая PIVNIK Bonus/POS production-функциональность не отключается решениями о SPACEVERSE SaaS.
