## Effective boundaries and what is NOT yet proved

1. **Admin Platform identity**: signed active `admin_sessions` + `admin_accounts` are checked by [auth.ts](https://github.com/GrafTrahula666/pivnik-bonus-app/blob/c92ed7cd65f1a96d94363c2b7e212424ab078a73/admin-platform/server/auth.ts). The top-level roles are only `SUPER_ADMIN` and `VENUE_ADMIN`; company grant is separately `owner/trusted`. `SUPER_ADMIN` can bypass company filtering, while `/api/admin/platform`, `/developer` and global `/audit` additionally use `requireSuperAdmin`.
2. **Normal venue API**: [router.ts](https://github.com/GrafTrahula666/pivnik-bonus-app/blob/c92ed7cd65f1a96d94363c2b7e212424ab078a73/admin-platform/server/router.ts) resolves `venues/:id` using `buildVenueScopeQuery`, then applies `requireVenueAccess` before dispatching. Non-GET requires CSRF. It is a *company-wide* grant model, **not a point-specific viewer/manager RBAC model**. Do not reinterpret it as one.
3. **Onboarding**: onboarding ACL has own roles, scope and revocation. [onboarding-access.ts](https://github.com/GrafTrahula666/pivnik-bonus-app/blob/c92ed7cd65f1a96d94363c2b7e212424ab078a73/admin-platform/server/onboarding-access.ts) includes per-draft checks and row-locking helpers for mutations, but this audit has not enumerated **every call site**. A `venue_id`-restricted invitation is not authority for other venues merely because `company_id` matches.
4. **CRM diagnostics**: [tenant-crm-read.ts](https://github.com/GrafTrahula666/pivnik-bonus-app/blob/c92ed7cd65f1a96d94363c2b7e212424ab078a73/admin-platform/server/tenant-crm-read.ts) enforces allowed draft and current source, uses a separate read-only transaction and rechecks before returning customer PII. It does **not** establish full general CRM mutation isolation, which belongs to steps 13–16.
5. **Legacy tenant isolation**: [data.ts](https://github.com/GrafTrahula666/pivnik-bonus-app/blob/c92ed7cd65f1a96d94363c2b7e212424ab078a73/admin-platform/server/data.ts) rejects a non-PIVNIK legacy adapter (`LEGACY_ADAPTER_NOT_TENANT_SAFE`) rather than pretending legacy `bar_customers` is a globally safe multi-tenant attribution source.
6. **Root compatibility authorization**: [authorization-middleware.js](https://github.com/GrafTrahula666/pivnik-bonus-app/blob/c92ed7cd65f1a96d94363c2b7e212424ab078a73/authorization-middleware.js) has a legacy-capability OR scoped-capability path. Never assume the helper is a canonical tenant gate or deploy it on a new tenant route without a route-specific security review and negative tests. Default-branch code search showed only module/test references.
