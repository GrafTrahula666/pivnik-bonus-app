# Поиск заведения в сети SPACEVERSE

В разделе «Заведения» введите название магазина или организации и нажмите
«Найти заведение». Поиск охватывает все доступные магазины, включая ещё не
подключённые черновики и магазины нескольких принадлежащих владельцу компаний.
Регистр букв не важен. «Показать ещё» продолжает тот же поиск, «Обновить
заведения» обновляет его результаты, «Сбросить поиск» возвращает всю сеть.
Пустой результат поиска не означает, что магазины исчезли или доступ отозван.

## Серверный контракт

Существующий GET `/api/admin/onboarding/venues?offset=0&q=...` принимает только
`offset` и `q`, по одному значению. `q` — до 100 символов без управляющих знаков;
пробелы по краям удаляются. Пустой запрос возвращает прежний контракт без `q`.
Непустой ответ содержит применённый `q`. Недопустимые параметры дают HTTP 400.

Фильтрация применяется к разрешённому и объединённому списку до пагинации:
25 строк на страницу, `total` и `nextOffset` относятся к совпадениям. `%`, `_`
и SQL-подобные строки — буквальный текст. Название не заменяет разрешение.
Текущие проверки grants при проекции черновиков сохраняются; поиск не выдаёт
доступ к данным другого бизнеса и не ограничивает собственника одной точкой.

Используется прежний default-off `ADMIN_ENABLE_ONBOARDING_WORKFLOW` и текущие
session/permission/rate-limit проверки. Новых флагов, миграций и настроек нет.
Поиск не запускает проверку подключения, не обращается к клиентской БД/кассе,
не меняет попытки и не подтверждает коммерческую активацию CRM.

Интерфейс сразу убирает прежние результаты после нового запроса; счётчик
запросов исключает поздний ответ. Ответ с другим `q` даёт понятную ошибку,
«Обновить заведения» повторяет текущий поиск.

## Изолированная проверка

С локальным test PostgreSQL и установленными test env:

```sh
npx vitest run server/tests/tenant-crm-activation.spec.ts server/tests/onboarding-workflow.spec.ts --maxWorkers=1
SPACEVERSE_E2E_OWNER_SEARCH=true SPACEVERSE_E2E_CRM_ACTIVATION=true npx playwright test -c playwright.tenant-crm.config.ts
```

Fixtures синтетические: 301 совпадение одной компании и магазин второй.

Реальная нагрузка тысяч клиентов не проверена: существующий список загружает
доступные metadata названий до фильтрации. Это ограничение фиксируется для
отдельного измерения, а не объявляется решённым этим PR. Production и устройства
не используются. Merge main запускает существующий production deploy; при
действующем запрете production этот шаг остаётся Draft PR.
