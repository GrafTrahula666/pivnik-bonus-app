# SPACEVERSE CRM — roadmap коммерческого SaaS

Дата: 18 октября 2026. Входные материалы: [аудит](SAAS-PRODUCT-AUDIT.md), [конкуренты](SAAS-COMPETITOR-RESEARCH.md), [Маркет](EVOTOR-MARKET-REQUIREMENTS.md), [архитектура аналитики/AI](SAAS-ANALYTICS-AI-ARCHITECTURE.md).

Главный маршрут: приглашение/установка → авторизация владельца → собственная компания/точка → разрешённый источник → подтверждённые данные → рабочая CRM → подтверждённая лицензия. Подготовленная metadata, сохранённый ключ, mock-ответ и оплаченный тариф — разные факты. Ни один не подменяет проверку связи.

## Приоритеты и порядок

P0 блокирует безопасную работу/коммерческую публикацию. P1 нужен для полезного минимального платного продукта. P2 расширяет ценность после рабочего критического пути. P3 — развитие по подтверждённому спросу. Несколько P0 могут идти как независимая подготовка, но в одном PR меняется только одна критическая подсистема.

Этапы после публикации выбираются по пилотам; обещание полного BI/AI не должно предшествовать работоспособной CRM. Товарная аналитика только читает разрешённые данные Эвотора. Закупки, склад, остатки, инвентаризация, рецептуры и производство в roadmap не включаются.

## Предлагаемая упаковка тарифов

Это проект состава, не опубликованные цены/лимиты. Соответствие единице лицензии Маркета проверяется до реализации оплаты.

| Тариф | Для кого | Предлагаемый состав |
|---|---|---|
| START | Одна небольшая точка | Основная CRM, поиск/карточки, подтверждённые продажи, базовые сегменты и отчёты, инструкции/поддержка |
| BUSINESS | Активная работа с базой | START + динамические сегменты, разрешённые кампании/триггеры, расширенные отчёты/шаблоны |
| PRO | Сеть/аналитическая команда | BUSINESS + разрешённая мульти-точечная аналитика, расширенные роли, очереди сложных отчётов и увеличенные лимиты |
| AI ADD-ON | Дополнительный анализ | Независимый entitlement и usage/budget; наличие PRO не включает AI автоматически. На текущем этапе только подготовка и mock |

Изоляция, аудит, безопасность, объяснение источников и базовый доступ владельца к своим данным не являются платным «улучшением безопасности». Поведение при окончании тарифа, read-only/экспорт и сроки хранения отдельно утверждаются; данные автоматически не удаляются.

Цена определяется после проверки: единицы/комиссии Маркета, налогов, облака/БД/backup, стоимости внедрения/поддержки, каналов сообщений и переменных расходов. Отдельно моделируются AI usage и support burden. Неизвестные ставки остаются неизвестными; комиссия не считается нулевой. Прайсы конкурентов с разным составом/регионом не дают корректной цены автоматически.

## Процесс каждой итерации

1. Свежий main и проверка пересечений с другими PR; одна SPACEVERSE-итерация/Draft PR за раз. Чужие открытые PR не закрывать и не присваивать их результаты.
2. Одна проверяемая задача. Новые production-модули — default-off; исправление уже существующей ошибки не требует включения нового модуля.
3. Осмысленные отрицательные тесты на scope, потерю ответа, пустые/недоступные данные. UI state isolation не заменяет server authorization.
4. До каждого пуша: materialize ×2 с побайтовой идемпотентностью, root node tests/check/audit, Business typecheck/vitest/build, применимые E2E. Generated diff server.js/universal-server.js/app.js записывается отдельно, не чинится молча.
5. Документы/MODULE-MAP/runbook и progress обновляются вместе с кодом. Итог: конкретный эффект для владельца, PR, команды/результаты, непроверенное и причины.
6. Merge/deploy только по отдельному разрешению текущего этапа. Существующий main workflow автоматически развёртывает Telegram/VK; это последствие раскрывается до запроса на merge. CI без отдельного разрешения не менять.

## Граница релиза

Внутренний green PR, готовность к модерации, прохождение Маркета и доступная платная установка — четыре разных состояния. Релиз требует нового клиента с изолированной CRM, проверенного подключения Эвотора, server-side лицензии, полной цепочки browser/HTTP/PostgreSQL и проверенных эксплуатационных инструкций. Внешние юридические/договорные действия перечисляются отдельно, без заявления, что инженер их выполнил.
