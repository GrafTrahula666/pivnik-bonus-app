## Изменения

Добавлен только `test/admin-adjustment-sql.integration.test.js` и этот отчёт.
Серверы, интерфейс, зависимости, миграции, env и patch-chain не изменены.
PGlite уже является devDependency проекта. Каждая фикстура использует отдельную
БД в памяти и HTTP-сервер на loopback со случайным портом.

Тест выполняет фактический код маршрута, auth/role middleware, request-key lock,
semantic replay helper и persistence adapter из проверяемой рабочей копии.
CREATE TABLE и восемь необходимых startup upgrades также берутся из server.js:
проверяются настоящие типы, CHECK, FK и UNIQUE. Session verification и
identity-role resolution заменены детерминированными провайдерами фикстуры;
подпись реального session token этим тестом не проверяется.

Проверено:

1. Начисление и списание сохраняют баланс и completed journal с клиентом,
   сотрудником, причиной, суммой, результатом и временем.
2. Точный повтор возвращает replay и не начисляет второй раз. Изменение суммы,
   причины, сотрудника или клиента при том же ключе возвращает 409; обе таблицы
   остаются без изменений.
3. Настоящая ошибка SQL CHECK при INSERT журнала после UPDATE кошелька
   возвращает ошибку, откатывает кошелёк и освобождает клиент. После удаления
   тестового ограничения тот же ключ успешно выполняется один раз.
4. Нет сессии — 401, сотрудник — 403; ноль, пустая причина и пустой ключ — 400.
   Транзакционное соединение не запрашивается, кошелёк/журнал не меняются.
5. Несуществующий клиент — 404, списание сверх баланса — 400; после rollback
   следующий корректный запрос успешно списывает до нуля.

Для владельца это подтверждение уже существующего сценария: повтор запроса
не удваивает корректировку, а ошибка журнала не оставляет баланс без записи.
Новых пользовательских возможностей и исправления production-поведения
этот test-only PR не добавляет.

## Проверки и ограничения

- Полная `npm run materialize` выполнена дважды; SHA-256 всех tracked файлов
  после первого/второго прохода совпадают. Первый проход изменяет прежние
  материализуемые файлы; эти изменения восстановлены и в коммит не включены.
- На материализованной копии `node --test`: **441/441**, 0 fail/skip.
- `npm run check` и `npm run verify:vk-startup-parity`: PASS.
- Новые пять сценариев также отдельно прошли на канонической копии после
  восстановления материализуемых файлов.
- После чистой `npm ci` по lockfile main повторены двойная материализация,
  SHA-256 сверка, полный `node --test` (**441/441**) и `npm run check`.
  Дополнительный запуск полного набора без материализации дал 417 pass /
  24 fail в существующих runtime/UI контрактах; все пять новых SQL-тестов
  прошли. Серверы/UI этого PR побайтно совпадают с main, эти прежние проверки
  ожидают материализованный runtime, как и release workflow. Это состояние
  исходников не исправлялось попутно.
- Полный `npm audit`: прежние **3 moderate**, 0 high/critical; отдельно
  исправляются в #180. Lockfile этого этапа не менялся.
- Публичный read-only production probe: **16/16** ответов; runtime сообщает
  release `18a0fa4`, ready/DB OK. Это не проверка авторизованной админки.
- Universal gateway отдельного обработчика корректировки не имеет: запрос
  проксируется в Express. В этом PR маршруты не менялись; proxy HTTP parity
  отдельно проверен в #182.

PGlite выполняет SQL транзакций, FK/UNIQUE/CHECK и advisory lock вызов, но эта
фикстура не доказывает конкуренцию независимых PostgreSQL-соединений или
сетевой сбой/неопределённый COMMIT. Запросы намеренно последовательны.
Tenant isolation будущей SaaS-платформы, реальные права владельца бизнеса,
реальные касса/Telegram и desktop/mobile UI остаются непроверенными.
UI этого этапа не менялся. Не было production write, миграций, рассылок,
merge или deploy.

Следующий небольшой этап: многосессионная проверка request-key/wallet locks
на отдельной тестовой PostgreSQL БД, когда такой стенд доступен. До этого
ревью уже открытого #182, без автоматического переноса чужих draft изменений.
