# CHAT 08 · Пункт 73 · календарь любого исторического дня

**Scope:** только проверка уже работающего выбора одиночной даты. Отдельная ветка от main `c92ed7cd65f1a96d94363c2b7e212424ab078a73`; Draft PR, без merge/deploy, production writes, новых API, изменения денежных формул и UI.

## Проверенное состояние до изменения

- `admin-platform/src/phaseC/SalesDashboard.tsx` уже имеет `type="date"` «Любой день», без `min`; `max` ограничивает будущие даты по Москве. Выбор формирует `?date=YYYY-MM-DD` и используется обоими POS режимами.
- `admin-platform/src/phaseC/ProductionDashboard.tsx` аналогично поддерживает дату для операций приложения.
- `admin-platform/server/evotor-read.ts:evotorPeriod` принимает любую валидную прошедшую одиночную дату, возвращает один московский календарный день, без максимальной глубины истории.
- `admin-platform/server/data.ts:parseOperationsPeriod` также допускает старые даты; **366 дней** относится только к длине диапазона, не к прошлому от даты запроса.
- Синхронизированная история Эвотора может быть неполной. Сам факт выбора 2021 года **не доказывает наличия кассовых документов**. Отсутствие документов и состояние неизвестного подключения не подменять выдуманными суммами.

## Минимальное изменение: регрессионные тесты, без переписывания функций

1. Server Evotor: старый одиночный день `2021-08-17`, московские полуоткрытые границы и один день.
2. Server app-operations: то же для `parseOperationsPeriod`.
3. React SalesDashboard: выбор `2021-08-17` отправляет `?date=2021-08-17`, нет `min`, режим all/app сохраняет дату без нового запроса.
4. Playwright POS browser: выбран `2021-08-17` спустя несколько лет от текущей даты фикстуры; синтетический ответ с нулевым объёмом чеков честно показывает `₽ 0,00` и пустые таблицы; исходные запросы и другие периоды продолжают работать.
