# Кассовая панель в PIVNIK Business

Добавлена вкладка «Все продажи кассы» рядом с «Программа лояльности» в существующем
обзоре заведения. Используются прежние карточки, шрифты, таблицы и чёрно-зелёная
палитра Business. Существующая аналитика программы лояльности не переписана.

Показатели кассы: выручка после возвратов, средний чек, число чеков продажи,
число операций (продажи + возвраты), суммы продаж/возвратов и их количество.
Дополнительно — выручка по дням и способы оплаты. Покупатели, повторные клиенты
и посещения по анонимным чекам не вычисляются. День определяется по Москве.

## Граница текущего этапа

Это UI-добавление. Рабочий Business API пока не передаёт кассовый отчёт, поэтому
вкладка показывает «Касса не подключена» / «Нет данных». Ручные суммы приложения
не подставляются вместо кассовых. API, авторизация, настройки, рабочая БД и касса
не изменены; новых запросов к серверу эта вкладка не добавляет.

Тип `CashReport` совпадает с необходимой частью подготовленного POS-ответа из
[PR #174](https://github.com/GrafTrahula666/pivnik-bonus-app/pull/174).
Для подключения серверный адаптер Business должен добавить `pos` к ответу
`GET /api/admin/venues/:venueId/dashboard`. Перед этим необходимо проверить
права на выбранное заведение, явное соответствие venue → магазин Эвотора и
точное совпадение московского периода с выбранным фильтром. Нельзя напрямую
переиспользовать сессию Mini App в Business или отдавать токен Эвотора браузеру.
Этот серверный адаптер в UI-этап не включён.

Показатели доступны только после полной успешной сверки. При отключении кассы
или до первой загрузки нет ложных нулей. При ошибке после успешной сверки
сохраняются последние суммы с предупреждением. Число чеков/средний чек остаются
неизвестными, если источник не передал число печатных чеков.

## Предпросмотр и проверки

`npm run build:web && node scripts/preview-cash-panel.mjs` создаёт автономный
[предпросмотр](preview/evotor-cash.html) из настоящей сборки Business UI.
В нём явно обозначены вымышленные данные, запросы подменяются только внутри
отдельного HTML и изменения отключены. Открыть файл локально, выбрать «Все продажи кассы».

Проверены typecheck, сборка frontend/backend, lint без ошибок и тесты Business:
52 passed, 14 существующих PostgreSQL integration tests skipped (тестовая БД
не настроена). Три новых проверки финансового UI проходят, включая точные
копейки за безопасным диапазоном floating point, отсутствие фиктивных нулей
и предупреждение при ошибке обновления. Реальное подключение Эвотора и приёмка
первого кассового чека остаются отдельным этапом.

В браузере проверены 1440×1000 и 390×844: оба раздела, общий фильтр «Сегодня»,
кассовые суммы/число операций, отсутствие вымышленных клиентских метрик,
отсутствие ошибок JavaScript и горизонтального переполнения. На узком экране
карточки идут в два столбца, таблицы остаются в пределах страницы.

Полный `npm audit` Business: 2 moderate, 3 high, 0 critical в прежних пакетах
`@playwright/test`, `playwright`, `brace-expansion`, `vitest`, `@vitest/mocker`.
Оба package/lockfile не изменены. Исправление зависимостей вынесено за рамки
этого UI-добавления; полный audit не объявляется зелёным.

Merge, production-деплой и изменения рабочих БД не выполнялись.

Общий GitHub release gate использует корневой `node --test` и устанавливает
только корневые зависимости. Он ошибочно захватывает десять прежних Vitest
файлов Business из базовой ветки без установки Vitest и потому не зелёный.
Новый кассовый тест назван `cash-dashboard.spec.ts` и явно включён в Business
Vitest: он выполняется при `npm test` в `admin-platform`, а корневой Node runner
его не захватывает. Прежние тесты и общий release gate не изменены.
Runtime audit Business: 0 vulnerabilities; замечания полного audit выше
относятся к существующим dev-зависимостям.
