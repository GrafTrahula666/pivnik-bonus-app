# Аудит платформенной интеграции

## Исходная архитектура

- `server.js` — Express API, PostgreSQL, Telegram initData, роли, бонусы, статусы, QR, магазин, рейтинг и админ-панель.
- `app.js` — единый клиентский интерфейс.
- `index.html` и `styles.css` — единая разметка и дизайн.
- Telegram API использовался для авторизации, вибрации и QR-сканера.

## Принятое решение

- Интерфейс не копируется: Telegram использует `/`, VK использует тот же `index.html` через `/vk`.
- `universal-server.js` маршрутизирует Telegram-запросы в существующий сервер и обрабатывает только VK-аутентификацию и платформенные маршруты.
- `vk-platform.js` подключает VK Bridge и предоставляет совместимый платформенный адаптер клиенту.
- Все бизнес-маршруты после входа используют существующий bearer-сеанс и исходную серверную логику.
- PostgreSQL остаётся единой базой; внешние идентификаторы вынесены в `user_identities`.

## Найденные Telegram-зависимости

- Проверка `initData` и Telegram bot token в `server.js`.
- `window.Telegram.WebApp` в `app.js`.
- `HapticFeedback` и `showScanQrPopup` в `app.js`.
- Telegram SDK и платформенные тексты в `index.html`.
- Telegram-уведомления владельцу в серверной логике.

Telegram-уведомления и исходная Telegram-аутентификация сохранены. Для VK добавлен отдельный безопасный путь входа по HMAC-подписи launch params.
