# PIVNIK: отдельный HTTPS-вход для кассы Эвотор

Подготовленный компонент для проверки нового сетевого маршрута. **На отдельном хостинге ещё не размещён; реальная передача из Эвотора и исправление таймаута не подтверждены.**

Прокси передаёт только три маршрута на фиксированный HTTPS-origin `https://pivnik-bonus-app-production-df60.up.railway.app`:

| Маршрут | Метод |
| --- | --- |
| `/api/health` | GET |
| `/api/device/pos/qr/resolve` | POST |
| `/api/device/pos/receipts/bind` | POST |

Данные, кошельки, tenant-изоляция, право списания и сумма покупки остаются на существующем сервере. Этот компонент не реализует списание бонусов. `/ready` проверяет только сам процесс и явно возвращает `upstreamVerified:false`.

Ключ передаётся в `X-Pivnik-Device-Key` на фиксированный origin. `Authorization`, cookies и служебные заголовки клиента не пересылаются. Проверка TLS upstream обязательна; перенаправления отклоняются, повторной отправки запросов нет. Разрешён JSON до 16 КиБ, ответ до 64 КиБ, ожидание upstream до 6 секунд, до 32 одновременных запросов. Ключи и тела запросов не журналируются. Сервер не принимает URL назначения из запроса или переменных окружения.

## Размещение без покупки домена

Timeweb Cloud App Platform [выдаёт бесплатный технический адрес с HTTPS](https://timeweb.cloud/docs/apps/upravlenie-apps-v-paneli#tehnicheskiy-domen). Backend-хостинг оплачивается отдельно: рекламный тариф для статического frontend от 1 рубля к этому серверу не относится. Аккаунт и точная цена выбранной конфигурации должны быть проверены перед заказом.

1. Создать отдельное Backend/Dockerfile-приложение из ветки с этими файлами. Основной PIVNIK и его БД не переносить. Для приватной сети выбрать отсутствие подключения, никаких секретов, токенов кассы или DATABASE_URL этому компоненту не требуется.
2. Выбрать минимальный подходящий сервер. В первую очередь проверить доступный регион вне проблемного маршрута, например Нидерланды, если он доступен для App Platform. Само название региона не доказывает доступность: нужны обе проверки ниже.
3. Dockerfile в корне, `EXPOSE 8080`, переменная `PORT=8080`, healthcheck `/ready`. Автодеплой оставить выключенным на время проверки. Внешний TLS завершает платформа; прокси проверяет TLS соединения до исходного сервера.
4. Получить выданный технический HTTPS-адрес. Проверить `/api/health` с нового хостинга до Railway и с российских контрольных точек до нового входа. Успешный `/ready` не заменяет эти проверки.
5. Только после успешных проверок добавить три точных URL в разрешения приложения Эвотора. Сохранить прежние URL для отката.
6. Затем собрать совместимый APK с новым фиксированным адресом и прежней постоянной подписью. **APK 1.0.11 пока использует старый адрес.** Смена origin требует проверенной миграции шифрованного ключа со старого origin; просто заменить строку адреса недостаточно.
7. На кассе проверить связь без ключа, потом сохранённый ключ, QR resolve, bind того же UUID чека, закрытие и однократное начисление. Списание требует отдельной реализации и проверки.

Прокси в России также может не достигать текущего Railway-origin; доступность нового входа и исходящего соединения проверяются независимо. При неудаче не менять адрес APK и не выдавать маршрут за исправленный.

## Локальная проверка

Node.js 22+, OpenSSL для временного TLS-fixture:

```sh
npm test
npm run check
```

14 интеграционных проверок используют локальный HTTPS-сервер с временным тестовым сертификатом. Временный private key создаётся только на время тестов и удаляется. Проверки не обращаются к production и не создают финансовых операций. Все 14 проверок прошли также на Node.js 22.23.3 из собранного Docker-образа; контейнер собран и прошёл локальную проверку `/ready`, отказа неизвестному маршруту и неверному HTTP-методу. Проверены UID 1000 и запуск с read-only root, без Linux capabilities. Digest базового образа закреплён в Dockerfile; результаты в CHECKS.json.

Запуск: `npm start`. Переменная окружения только `PORT` (по умолчанию 8080). Docker-контекст включает только `server.mjs`, `package.json` и Dockerfile; тестовые файлы, сертификаты, документы и окружение в образ не попадают.
